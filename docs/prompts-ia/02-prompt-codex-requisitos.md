# PROMPT PARA CODEX — ELABORACIÓN LOCAL DE REQUISITOS E HISTORIAS DE USUARIO

Actúa como un analista de requisitos de software con experiencia en ingeniería de software e inteligencia artificial generativa.

Estamos desarrollando el proyecto académico **Caso 02 – Generador Inteligente de Reclamos de Consumo**, correspondiente al Seminario de Ingeniería de Software con IA Generativa.

Necesito elaborar localmente el documento `02-requisitos.md`, aplicando la metodología **R.E.C.E.T.A.** para estructurar las instrucciones y el formato **Gherkin (Dado / Cuando / Entonces)** para los criterios de aceptación.

## Contexto del proyecto

El sistema permitirá a los consumidores describir problemas con productos o servicios, registrar los hechos, identificar información faltante, consultar normativa ecuatoriana mediante inteligencia artificial y generar borradores de reclamos para revisión del usuario.

La solución contempla React y TypeScript, Java con Spring Boot, Spring AI, ChromaDB y SQLite.

## Actividades solicitadas

1. Analiza la descripción del Caso 02 y las necesidades identificadas.
2. Organiza las necesidades de los consumidores mediante identificadores.
3. Define 11 requisitos funcionales, identificados RF-01 a RF-11.
4. Redacta 11 historias de usuario, identificadas HU-01 a HU-11.
5. Para cada historia utiliza la estructura:
   - Como [tipo de usuario].
   - Quiero [funcionalidad].
   - Para [beneficio].
6. Incorpora criterios de aceptación en formato Gherkin:
   - **Dado** que [condición inicial].
   - **Cuando** [acción del usuario].
   - **Entonces** [resultado esperado].
7. Define 11 requisitos no funcionales, RNF-01 a RNF-11.
8. Documenta las reglas de negocio y restricciones.
9. Relaciona las necesidades, los requisitos y las historias mediante una matriz de trazabilidad.
10. Identifica los puntos que necesitan validación con fuentes oficiales.

## Reglas de elaboración

- Redacta en español académico, claro y natural.
- No inventes leyes, artículos, plazos ni fuentes.
- No confundas funcionalidades propuestas con funcionalidades implementadas.
- Considera la protección de datos personales y la autorización expresa del usuario.
- Los criterios de aceptación deben permitir comprobar posteriormente el funcionamiento del sistema.
- Mantén coherencia entre las necesidades, requisitos e historias de usuario.
- Identifica las afirmaciones pendientes de validación.
- No elimines funcionalidades sin justificarlo.

## Resultado esperado

Genera el contenido completo del documento `02-requisitos.md`, en formato Markdown, con títulos, tablas, requisitos, historias de usuario, criterios de aceptación y matriz de trazabilidad.

El documento debe quedar preparado para revisión académica y posterior implementación.

Trabaja únicamente con archivos locales. No utilices GitHub, no ejecutes comandos Git, no crees ramas y no publiques información en repositorios.

Antes de guardar el documento, presenta su contenido para revisión.
